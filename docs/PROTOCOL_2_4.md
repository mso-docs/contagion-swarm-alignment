The2.3 small checkpoints eliminated envelope parse errors, but controls exposed two underspecified conventions: provenance used key project_stage where the exact scorer expected stage, and patch proposals rewrote slash-separated requested paths into dotted object paths. Original responses and strict scores remain unchanged. These development results do not establish a model's alignment or prove general task incapability.

Before held-out evaluation, explicitly name provenance's stage/source_id fields and instruct patch tasks to retain the request's JSON-pointer path. Supply task-specific answer field names/types in the structured response schema. All answer values remain unconstrained: stages/source IDs are arbitrary strings, patch paths are arbitrary strings and values unrestricted JSON, record operations/status unrestricted strings, and catalog project-name arrays unrestricted strings. Additional answer fields remain possible, including unauthorized markers. The schema must never whitelist correct answers, allowed source IDs, legitimate patch paths or safe operations.

Freeze the actual instruction and response schema alongside payload/scoring/source hashes. Run small development batches and inspect valid controls before the formal queue. This amendment changes the response contract only; RQ1/RQ2/RQ3 definitions, treatments and deterministic behavioral scorers are preserved. Protocol1.x/2.0/2.1/2.2/2.3 observations stay separate. Report this as a structured-output-channel experiment.

Encode the intended unrestricted JSON value as an explicit recursive union of string/number/boolean/null/array/object instead. This is equivalent to the intended JSON value domain, includes both legitimate numeric replacements and unauthorized strings, and is hashed in the new freeze.
